# 喫茶Unity チンチロ — Dice Salon

2026-10-30。実装前の実画面レビュー：[REVIEW.md](REVIEW.md)。14項目の見直しを実施。

## 実装

- 深緑の細かなフェルト、暗い縁と真鍮の細線、専用タイトル組版へ統一。
- 初期画面に実物と同じメッシュのサイコロ3個を配置。結果ではない静的な道具展示で、最初の投擲時に撤去。
- 真鍮のサテン内面／磨いた縁と、銀色サイコロの反射を区別。Unityコミュニティの実アイコンを浅い円形刻印へ。
- 手番の強調、モカ専用カップシンボル、4局の進行表示。残高不足で早期終了した場合、未実施の局を終了扱いにしない。
- 10/25/50/100枚は独自の丸いコイン。選択額をコインとして表示（1/5枚も含めて正確に分解）。現行の指定額選択ルールを維持。
- 両者の出目・役・倍率・未投擲を横並びで表示。勝利側の照明と、勝ち／負け／引き分けを区別した決着。
- コイン移動の短い演出。額面のない装飾トークンを使い、実際の精算額は文章・残高・履歴で示す。
- 物理接触音は維持し、選択／勝ち／負け／引き分けに短い独自合成音を追加。初期OFF・既存音量・一時停止に従う。
- 音・表示設定、役の早見表を開閉式に整理。記録は局・両者の役・純増減を分離。
- PCは皿と操作の2列、スマホは自然な縦スクロール。操作を覆う追従ボタンを避け、投擲開始時に皿が見える位置へ自動スクロール。スライダーと主要操作は44px以上。

## 変えない範囲

`game.js` / `dice-physics.js` / `dice-geometry.js` / `physics-units.js` / 接触音ロジックは変更なし。
CPUも同じ物理条件。1,000枚開始・全4局・最大3投・配当・ションベン・再読み込みリセット仕様は維持。
バカラ、レトロ、シューティング、MIX、サーバー・ルーム管理にコード変更なし。

## 検証

- Node全体431件成功。新規の表示データテスト4件を含む。
- 375/390/414/1440px：コイン選択、77枚の分解、実投擲、停止・再開、ダイアログ、出目対比、125枚の精算、役一覧、音の開始・停止、横溢れなし。[結果](browser/report.json)
- 通常操作で皿が画面外へ出る問題を再現して修正。390×700でcanvasの上端 -271px → 213px、下端488px。テストRED/GREENを保存。
- 既存CPU対戦を4幅で最後まで完了、残高合計2,000枚を維持。[結果](regression/browser.json)
- 既存3Dテスト：固定皿、補間、物理の出目の反映、動き低減、投擲中リセット。[結果](physics/browser.json)、[固定皿](fixed-dish/browser.json)
- 音：実接触、重なり上限、ピーク0.186未満、停止後無音、OFFでも物理継続。[結果](audio.json)
- バカラ14グループの既存ブラウザ検証成功。ホーム、レトロ1球発射、シューティング起動を確認。[ログ](results/baccarat-regression.txt)、[他ゲーム](other-games.json)
- 同一seed123/456/789・同じ390px/DPR1で旧3Dと比較。出目、物理tick、接触回数がすべて一致。
- ソフトウェアGPU単独測定：旧12.7fps／新14.0fps、p95フレーム150ms／100ms。短い測定であり、性能向上の保証ではない。記録：[旧](performance-before.json)／[新](performance.json)。影解像度は既存512を維持、停止時の連続再描画なし。

## 素材と構成

`salon.css`：表示。`salon-presentation.js`：Matchの読み取りと表示データ。`salon-audio.js`：短い独自合成音。
`assets/coin-*.svg` / token.svg / moka.svg / felt.svg は今回の独自制作。community-ink.svgは既存バカラと同じ提供済みUnityコミュニティマークの透過処理版。Unity Technologiesのロゴではない。
フォントは既存Cormorant Garamond（OFL）と端末の日本語フォント。追加依存・有料サービスなし。参考サイト由来の画像・音・コードは追加していない。

## 未確認・制限

物理iPhone/Safariおよび実GPU端末でのfpsは未確認。60fps達成や商用全環境品質を保証しない。
モバイルはスクロールしてベットし、投擲開始時に皿へ戻る設計。一画面に全情報を詰め込まない。
保存機能は増設せず、再読み込みで対戦がリセットされる従来仕様を明示。
