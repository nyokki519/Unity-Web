# Unity MIX イベントゲーム

既存6モードのMIXに加えて、対面の6〜15人向けに次のゲームを選べます。登録不要。司会がルームを作り、同じサーバーのQR／4桁コードを共有します。全員が準備できたら開始し、説明画面からお題と時間を選びます。

| ゲーム | 入力と進行 | 公開範囲 |
| --- | --- | --- |
| 価値観ランキング | 4〜5項目をドラッグ／上下ボタンで並べ替え→締切→平均順位・分布→会話 | 個別順位は本人だけ、全員には匿名集計 |
| この回答、誰でしょう？ | 120文字→匿名回答を一件ずつ予想→予想締切→正解→本人が話す | 正解公開まで回答者は非配信。自分の回答に投票不可 |
| みんなの境界線 | 0〜100→締切→匿名分布・平均・範囲→会話 | 自分の位置は本人のみ。名前と数値を結びつけない |
| 共通点クエスト | 2〜4チームで相談→代表が300文字以内で提出→締切→司会承認→発表 | 締切前はチーム回答の代表だけ。公開後はチーム名と回答 |
| 架空のカフェ会議 | 立地・メニュー・内装、店名・コンセプト→予算内で代表が確定→発表 | 下書きは同チームだけ、確定案は締切後に公開 |
| エピソードの持ち主 | 見出し40文字＋体験談600文字→一件ずつ読む・予想→正解→本人が話す | 短文版と同じ匿名保護、本人の会話は目安120秒 |

各ゲームに15題、計90題を追加しています。既存252題は保持しています。共通点は「気軽・ひと工夫・じっくり」に各5題。司会は説明画面でお題・会話の問い・難易度・選択肢・カフェの費用／予算を編集し、新しいお題として追加できます。変更はそのルームにだけ保存され、共有データファイルや進行中のお題は変わりません。

## 10〜20分で遊ぶ

個人・チームゲームは標準3ラウンド。回答は90秒、チーム相談と体験談は180秒、予想は45秒。司会が30〜600秒に変更できます。対面の会話時間は司会が判断し、早期締切もできます。

匿名ゲームは標準1ラウンド。短文はランダムに最大6件、体験談は最大4件を公開します。15人の体験談を全部読むと会話時間だけで30分を超えるためです。全員の提出は受理しますが、選ばれなかった回答は他の人に公開されません。このルールは全員の画面に表示されます。司会は開始前に公開件数を1〜15件で設定できます。全件・複数ラウンドを選ぶ場合は所要時間が延びます。

短文では正解公開後の本人の会話を目安45秒、体験談は120秒とし、いずれも自動で会話を打ち切りません。話したくない回答・予想はパスできます。チーム代表以外も個人としてパスできます。

## 司会の操作

- 説明→回答／相談の開始→締切→公開→会話→次のラウンド／終了。
- 匿名ゲームは「予想を締め切る」「正解を公開する」「次の回答へ」を分けています。
- チームは均等自動分け、または手動分け。接続中の同チーム参加者に代表を引き継ぎます。
- 締切後にテキスト回答を確認して非表示にできます。匿名の確認画面でも、回答者名は表示しません。非表示内容は以降の配信と正解公開から除きます。
- 管理欄から参加者を退出、ゲームを切替、終了できます。退出したセッションは無効です。
- 未回答者がいても締切後に公開できます。未回答とパスを区別します。

カフェ案は合計と残額、予算超過を表示します。予算内・全カテゴリ選択・店名／コンセプト記入が確定条件。サーバーも選択肢IDから費用を再計算し、予算超過を拒否します。下書き共有だけでは提出済みになりません。好みへの採点はしません。

## 通信・復旧・保存

サーバーが状態を保持し、端末の復帰トークンで同じ参加者として戻ります。画面は送信中と受理済みを区別し、通信不良時は送信しません。下書きはタブのsessionStorage、確定回答はサーバーの状態を優先します。同じ参加情報を別タブで使った場合は後のタブを優先します。

途中参加は次のラウンドから。司会の切断後12秒で接続中の参加者に司会権限を移し、旧司会が戻っても権限を勝手に戻しません。全員切断時も同じDBを使えば復帰できます。タイマーはサーバー時刻で進むため、切断中にも締切になります。

未使用24時間、終了後1時間でルームを削除対象にします。復帰用トークンの生値はDBに保存せず、DBは静的配信しません。非表示にする前に閲覧された内容を端末から回収する機能はありません。

## 起動と検証

```bash
cd /workspace/Unity-Web
npm ci --ignore-scripts --cache /workspace/.npm-cache --no-audit --no-fund
npm start
```

Node.js 24以上。標準はポート3000、DBは`.data/rooms.sqlite`です。開発時は`npm run dev`も使えます。複数端末では同じ到達可能なサーバーの住所を使います。

```bash
npm run check:questions
npm test
python3 test/browser_check.py --url http://127.0.0.1:3000
python3 test/events_browser_check.py --url http://127.0.0.1:3000 --people 6 15
```

ブラウザ検証はPython Playwright、Pillow、`/usr/bin/chromium`が必要で、実際にテストルームを作ります。専用インスタンスで実行してください。イベントUI検証は本番レート制限を守る操作間隔を入れているため数分かかります。

公開時に必要なのはHTTPS／WSS、確認済み`PUBLIC_URL`、非公開の永続`DATA_PATH`、単一Nodeプロセスです。複数インスタンスへの水平分散には対応しません。新しい有料サービスやAPIキーは必要ありません。今回、本番公開・Render操作は行っていません。

実際のiPhone／Android、会場Wi-Fi、外部HTTPS／WSS、OSの共有シートは別途実機確認が必要です。
