# UNITY MIX 設計・運用

## 目的と選択した構成

同じ場所にいる人同士が、違う答えとその理由を楽しむゲーム。画面に滞在するより、目の前の人と話す時間を大切にする。

既存ロゴのカップとハート、アイボリー、落ち着いたオリーブ、既存のセリフ体を継承。旧HPのページ・プロフィール・イベント写真はゲームの構成に含めない。旧HPは作業時にリポジトリ外へアーカイブし、ブランドの原本を照合してから整理した。

一つのNode.js 24プロセスにHTTPとWebSocketをまとめる。Firebase / Supabaseとの比較では外部認証・運用設定を増やさず、秘密回答をサーバー側で確実に扱える構成を選択した。クライアントは軽量なネイティブES Modules。SQLiteは再起動復帰のために使い、リアルタイムはWebSocketで同期する。

## 分離した責務

| 層 | ファイル | 責務 |
| --- | --- | --- |
| 接続・HTTP | `src/server.js` | 静的配信、ルームAPI、認証、QR、レート制限、heartbeat、配信 |
| 状態遷移 | `src/engine.js` | プレイヤー、準備、参加者の確定、回答、公開、会話、進行、引き継ぎ |
| モード | `src/modes/` | 入力の正規化・検証、公開結果、値の集計 |
| 出題 | `src/questions.js`, `data/` | カテゴリ・深さ・有効フラグでプールを選ぶ |
| 最終集計 | `src/summary.js` | グループと本人のまとめ、集計根拠 |
| 保存 | `src/store.js` | 非公開のSQLite、期限、削除 |
| UI | `public/js/` | 画面・入力・結果のモード別レンダラー、接続復帰、共有画像 |

モード追加は、サーバー側の `validate / result / scores`、クライアント側の入力・結果レンダラーをレジストリへ登録し、質問を追加する。モードのルールをサーバーや画面の一つの巨大な条件分岐に集約しない。

## 状態遷移

`LOBBY → ANSWER → COUNTDOWN → TALK → ANSWER … → FINAL → LOBBY`

- START：接続中の全員が準備OK、かつ2人以上。
- ANSWER：お題の開始時に参加者を確定。途中参加は待機して次のお題から。
- REVEAL：全参加者が回答またはパスした後のみ。自動とホスト手動を選択可能。
- COUNTDOWN：サーバーの時刻に基づく3秒。公開結果はまだ配信しない。
- TALK：結果と会話の問いを全員に配信。次に進むのはホスト。
- FINAL：公開済みのラウンドのみを集計。回答途中に終了しても未公開回答を集計・露出しない。
- PAUSE：回答・カウントダウン・会話を止める。公開までの残り時間を保持。
- SKIP：そのお題を進める。回答中の値は集計しない。
- QUESTION CHANGE：同じラウンドの新しいお題へ。旧回答をリセット。

失敗したコマンドは状態を巻き戻す。古いroundId、二重回答、非ホストの進行操作、入力範囲外はサーバーで拒否する。

## 秘密回答と本人の結果

クライアントへはプレイヤー別の `view` のみを送信する。回答前には本人の答え、回答人数、回答済みフラグだけ。他人の回答辞書や集計結果は送らない。

| モード | 公開内容 | 本人のみ |
| --- | --- | --- |
| ALIGN | 二択の人数・割合・選んだ人の名前 | 公開前の自分の回答 |
| PREDICT | 本人の答え、的中人数・名前 | 公開前の回答・予想 |
| LINE | 匿名の位置・平均・最小・最大 | 自分の位置 |
| RANK | グループ順位 | 自分の順位 |
| AUCTION | グループ平均 | 自分の配分 |
| QUICK MIX | 名前と短文、口頭参加 | 公開前の入力 |

YOUR MIXはその参加者だけに配信。共有カードは本人が画像を保存・共有するまで外部へ送らない。ルームコードを知る人は参加できるため、秘密の会話用の強い本人確認システムではない。

## 再接続

暗号学的乱数による256bit復帰トークンを端末へ保存し、サーバーにはSHA-256のハッシュだけを保存する。トークンはWebSocketの最初のメッセージに載せ、URL・ログ・QRに入れない。本番ではHTTPS / WSSが前提。

同じ参加情報を複数タブで使うと後のタブを優先。クライアントは4001の切断で自動再試行せず、再接続ボタンを案内する。古いソケットのイベントで新しい画面や接続を上書きしない。

ホストが切断すると12秒間待ち、接続中の参加者のうち参加順の早い人へ移す。復帰した元ホストは同じ人物として戻り、現在のホスト権限は保つ。全員切断時はルームを保持し、再接続で復帰する。

未回答の人が切断した場合は自動的に答えを推測しない。復帰を待つか、ホストがそのお題をパス扱いにする。参加者本人の退出もそのお題のみパスとする。

## 一時保存と期限

ルームは最後の活動から24時間、ゲーム終了後は1時間の期限。稼働中の100msタイマーと起動時の読み込みで期限を確認する。期限切れのルームはDBとメモリーから取り除く。SQLのsecure_deleteと削除後のWAL checkpointを使う。バックアップ・インフラのログに回答内容を追加しない。

`.data` とDBは静的配信対象外。ディレクトリは700、DBは600で作成。公開サーバーでは専用の非公開永続ディスクを使う。水平分散は未対応。二つのプロセスが同じDBを使う構成にしない。

## 集計の意味

二択は対応タグの選択率、LINEは両端に対する位置、RANKは順位を0〜100へ正規化、AUCTIONは配分したポイント。個人内で観測した項目を平均し、その後グループをプレイヤーごとに平均する。PREDICTはターゲット本人だけを集計し、他人への予想は本人の価値観として扱わない。QUICK MIXの短文をAI等で心理分析しない。

質問ごとの観測回数も表示する。項目間の合計は100ではなく、問いの種類によって数値の意味も異なる。性格の断定や、科学的な診断の主張はしない。共有カードにもその旨を記載する。

## 質問追加・変更

`data/questions.json` の一つの項目：

```json
{
  "id": "unique-id",
  "mode": "ALIGN",
  "category": "LIGHT",
  "depth": "LIGHT",
  "question": "カフェで選ぶなら？",
  "choices": ["いつもの一杯", "初めてのメニュー"],
  "talkPrompt": "その一杯を選ぶ理由を聞いてみよう。",
  "valueTags": {"a": ["stability"], "b": ["curiosity"]},
  "enabled": true
}
```

カテゴリと値のラベルは `data/catalog.json`。IDは変更せず、無効化には `enabled: false` を使う。既存のゲーム中のお題は生成時のコピーを使う。追加・変更後は `npm run check:questions` と `npm test`。管理画面・DBの質問管理へ進める場合は、出題サービスを同じインターフェイスで置き換える。

## PWA・通信・安全性

HTTPSでシェルをキャッシュできるPWA。リアルタイムのゲームそのものをオフラインで進行させない。APIやWebSocketはキャッシュ対象外。復帰用セッションがある端末では同じルームへ戻れる。

CSP、同一originの確認、HTTP/接続/操作のレート制限、8KB受信上限、heartbeatを実装。入力はDOMのtextContentで表示する。カード画像とQRはローカルの処理で生成し、外部解析や広告サービスを使わない。

実際のiPhone Safari・Android、PWAのインストール、OSの共有シート、外部ドメインでのHTTPS/WSSとQRの検証は本番公開後の確認項目。Dockerfileはビルド・コンテナの通し検証済み。GitHub Actionsのリモート実行は別途確認が必要。
