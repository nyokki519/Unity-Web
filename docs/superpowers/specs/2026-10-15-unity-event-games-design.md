# Unity MIX 対面イベント用6ゲーム設計

## 目的と範囲

20代中心のカフェコミュニティで、6〜15人が各自のスマートフォンと司会のスマートフォン／PCを使い、対面の会話を楽しむ。各ゲームは10〜20分を目安とし、入力より相談・発表の時間を中心にする。登録不要、ニックネーム、ルームコード／QR参加、回答スキップを提供する。

`deploy/unity-mix` の既存ALIGN・PREDICT・LINE・RANK・AUCTION・QUICK、おまかせMIX、結果・共有を保持する。既存6モードを「既存のMIX」として残し、その隣にイベント用6ゲームを追加する。RANKとLINEの入力・集計処理は共有できるが、既存モードの公開範囲や動作を勝手に変更しない。Unity Analytics、別サービスのQR、DROPは対象外。アプリ内の既存参加QRは継承する。

本番公開、Renderへのデプロイ、サイト削除、APIキー再発行、有料サービス契約は行わない。実装・検証・起動手順をレビュー可能な状態にする。

## 構成

既存のNode.js 24以上、ネイティブES Modules、WebSocket、SQLiteを使用する。新しい外部サービスや認証は追加しない。単一Nodeプロセスでサーバー状態を管理する。

- `src/engine.js`：既存ルームの認証、接続、権限、保存を維持し、イベント進行へ委譲。
- `src/events/`：イベント共通の状態遷移、公開用ビュー、チーム・司会操作、ゲームごとの検証と結果を分離。
- `data/event-questions.json`：6ゲームそれぞれ最低15個の即使用可能なお題。
- `public/js/events/`：司会画面、参加者入力、公開結果、説明、チーム相談画面。
- 既存の画面・モード選択：イベントゲームを追加し、既存モードとの区別を表示。
- テスト：イベント状態遷移、実HTTP/WebSocket、独立ブラウザを別々に検証。

SQLiteの既存JSON保存方式を継承し、古いルームには新フィールドの既定値を適用する。既存セッションの復帰と既存ゲームの進行を壊さない。

## 共通進行

イベントは `LOBBY → RULES → ANSWER/CONSULT → REVEAL または GUESS → TALK → 次ラウンド → FINAL`。

司会だけが開始、締切、公開、正解公開、次ラウンド、ゲーム切替、終了を操作する。予想系は締切と正解公開を別操作にする。回答公開で初めて会話を始め、スマートフォンを置く案内を表示する。

回答・相談・予想の締切はサーバーの時刻で管理し、既定値は回答90秒、チーム相談180秒、予想45秒。司会は開始前に30〜600秒で設定でき、早期締切も可能。締切後の未回答は未回答として区別して集計から外し、回答を捏造しない。スキップも別状態で表示する。公開は全員回答済みでなくても締切後に可能。相談終了後の発表・会話は司会が進行する。

途中参加者はルームに入り次ラウンドから回答可能。退出・司会による退出で回答待ちを止め、退室済みセッションの操作・復帰を拒否する。切断では回答を消さず、リロードと再接続でサーバーの現在状態を受け取る。既存の12秒後の司会引継ぎを維持する。

司会がゲームを切り替えると説明へ戻り、新しいラウンドIDを発行する。すでに公開済みの記録は保持し、未公開回答を最終結果や共有カードへ混ぜない。

## 6ゲーム

### 1. 価値観ランキング

4〜5個の選択肢を全員が並べ替える。既存RANKのドラッグと上下ボタンを再利用する。公開後は平均順位と分布、本人の順位を表示し、共通点と違いを話す。個別順位は本人にだけ送信し、全員には匿名分布を送る。お題編集で選択肢も編集できる。

### 2. この回答、誰でしょう？

120文字以内の短文を匿名で集める。締切後に回答を一件ずつ表示し、参加者名から回答者を予想する。回答者本人には投票UIを表示せず、サーバーでも本人からの投票を拒否する。候補一覧から本人だけを除外すると匿名性を壊すため、他の人には候補一覧を共通に送る。

`回答収集 → 匿名回答表示・予想 → 予想締切 → 正解公開 → 本人が話す（目安45秒） → 次の回答`。予想もスキップ可能。投票数だけを予想中に公開し、回答者ID・予想内容・正解は締切前に送らない。

### 3. みんなの境界線

0〜100のスライダーで数値を回答する。両端の意味をお題ごとに示す。締切後に匿名分布、平均、最小、最大と本人の位置を表示する。ルールに「他の人には名前と数値を紐づけて公開しない。自分の数値を話すかは自由」と明示する。

### 4. 共通点クエスト

司会が2〜4チームに分ける。人数に応じた均等自動分けと、開始前の手動変更を提供する。各チームに代表提出者を示し、代表が300文字以内の共通点を提出する。相談は対面で行い、アプリ内チャットは作らない。

難易度は「気軽・ひと工夫・じっくり」。各難易度最低5題。締切後にチーム名と回答を公開し、司会が承認または確認待ちを表示する。優劣の自動採点は行わない。代表が切断・退出した場合は接続中の同チーム参加者へ代表を移す。途中参加者のチームは次ラウンド開始時に割り当てる。

### 5. 架空のカフェ会議

同じチーム基盤を使用。架空の予算100万円を標準とし、立地・メニュー・内装の各カテゴリから一つずつ選択し、店名40文字以内とコンセプト300文字以内を添える。代表が入力し、同チームには相談中の案を共有する。他チームには締切前に送らない。代表権限は明示する。

費用はサーバーが選択肢IDから計算し、画面にも合計・残額・予算超過を表示する。全カテゴリ選択と予算内を確定条件にする。予算超過の確定はサーバーで拒否する。締切時に未確定の案は未提出として扱う。公開後に全チームの案を発表し、正解・不正解や好みへの採点はしない。15個のお題は異なる客層・立地条件などの企画条件を持つ。

### 6. エピソードの持ち主

600文字以内の体験談と40文字以内の見出しを集める。短文版と異なり、記入は「きっかけ・起きたこと・今思うこと」の案内付き。回答時間は180秒を標準にする。一件ずつ全文を読み、予想を締め切り、正解公開後に本人の会話時間を目安120秒とする。時間は強制終了せず司会が次へ進める。

短文予想と匿名投票の仕組みを共有し、入力・読む画面・会話時間・案内を分ける。自分の体験談には投票できない。予想と体験談はスキップ可能。

## お題編集・司会管理

各ゲームの選択画面で司会が15題以上の一覧から選び、ルーム内だけの追加・編集・無効化を行える。共有のお題ファイルは参加者操作で変更しない。開始したお題はコピーとして固定し、編集中の変更を回答中のラウンドへ反映しない。文字数、選択肢数、数値範囲、費用はサーバーで検証する。

司会には回答収集の締切後に不適切なテキストの確認・非表示操作を提供する。匿名ゲームの司会用一覧にも正解公開前の回答者対応表は送らない。非表示にした回答は参加者ビュー、予想候補、公開結果、最終記録から除き、現在表示中なら即時に非表示状態を配信する。非表示済み回答者を後の正解公開で漏らさない。

## 通信・権限・匿名保護

ブラウザにはプレイヤー別に加工したビューだけを送る。締切前の他人の回答、匿名回答と回答者IDの対応、復帰トークン・ハッシュを送らない。同チームへのカフェ相談案の共有はルールで例外として明示する。

匿名回答の表示IDはランダムに生成し、参加順・回答順・プレイヤーIDと結びつかない順に表示する。正解は司会の正解公開操作後、現在の一件に限り公開する。次の回答の正解は伏せたままにする。

状態変更コマンドにはラウンドIDと状態リビジョンを付け、古い画面からの進行操作を拒否する。二重回答・二重投票・連打はサーバー側で拒否または同じリクエストの結果を返し、状態を二重に進めない。失敗コマンドは既存のロールバックを利用する。

通信不良時は再接続案内を表示し、送信ボタンと進行操作を抑止する。「送信済み」はサーバーで受理された状態を受け取った後だけ表示する。下書きは端末内に保持し、再接続時に勝手に締切後の送信をしない。送信中・未送信・受理済みを区別する。

ルームは最後の活動から24時間、終了後1時間で削除対象。既存SQLite削除処理を継承し、ルール・プライバシー画面に明示する。

## 画面

深緑とアイボリー、既存Unityのロゴ・書体を継承。390px幅でも横スクロールなく、日本語の長文は折り返す。操作ボタンは44px以上を目安にする。

司会画面は人数・回答数・タイマー・現在の進行段階・締切／公開／正解／次への操作を優先。参加者画面は回答／予想／相談の一つの主操作を優先する。ルールには公開範囲とスキップを常に記載する。

公開時の軽いフェードは `prefers-reduced-motion` で抑止し、画面内にも動きを減らす切替を設け端末に保存する。キーボード操作、フォーカス、ラベル、通信状態の読み上げを確認する。

## 実装順序

1. 共通イベント状態、説明、タイマー、権限・リビジョン、編集、司会管理、チーム、保存とビュー。
2. ランキングと境界線。既存処理を共有し既存モードを回帰検証。
3. 短文予想。匿名収集、個別予想、締切、正解公開、本人の会話を実装。
4. 共通点クエストとカフェ会議。チーム代表、承認、費用・確定を実装。
5. 体験談予想。共有ロジックに長文入力と異なる進行時間を追加。
6. 全6ゲーム各15題以上、司会編集UI、モバイル・接続表示を仕上げ、通し検証と手順を記録。

## 完成検証

- 各ゲームで参加→説明→回答／相談→締切→公開→会話→次ラウンド→終了を実行。
- 実HTTP/WebSocketの6人・15人構成で同期、途中参加、退出、再接続、司会切断・引継ぎ、サーバー再起動復帰を確認。
- 独立したブラウザコンテキストで6人・15人の進行と390px画面を確認。単一端末デモを複数人完成の根拠にしない。
- 120／600文字、長い名前、スキップ、全員スキップ、未回答、全員切断、期限到達、二重送信、古い操作、予算超過、不正IDを検証。
- 非司会による進行・編集・退出操作、他チーム案の取得、自分への投票を拒否することを確認。
- 配信JSONを検査し、締切前の回答、匿名回答者の対応表、非表示内容が漏れないことを確認。
- 既存15テスト、252問チェック、既存ブラウザ通し検証を回帰実行。
- 起動は既存 `npm ci --ignore-scripts --cache /workspace/.npm-cache` と `npm start`。公開に必要なHTTPS/WSS、確認済みPUBLIC_URL、非公開永続DATA_PATH、単一プロセス制約だけを文書に記載。本番公開はしない。
- iPhone／Android実機、外部HTTPS/WSS、OS共有、実会場Wi-Fiは未確認事項として区別する。
