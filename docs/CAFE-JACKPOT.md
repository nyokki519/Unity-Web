# 琥珀の三段塔 — カフェの大穴チャレンジ

Unity MIXのホームの「おまけ / ひとりで遊ぶ」から起動する、オリジナルの1人用遊技台。ルーム作成・参加・登録なしで遊べる。既存の交流ゲーム、CPU参加者、サーバーのルーム処理は変更しない。作品の台・キャラクター・画像・セリフ・音楽は流用していない。

## 遊び方

1. 「練習」「通常」「高難度」を選んで開始。初期玉は100球。
2. スライダーまたは＋／−で強さを調整し、「1球発射」または長押しで発射する。
3. 釘の盤面の入口を通ると1段目へ。各段の金色の穴を突破し、3段目で大当たり10,000点。暗い穴は回収。
4. 残り玉と動いている玉が両方0になるまで遊ぶ。途中終了・一時停止・再挑戦もできる。

Spaceで1球発射、台を選択した状態で←→は強さ、Pは一時停止。連射ボタンをキーボードで選択してSpace／Enterを押している間も連射できる。ボタンからフォーカスが外れると連射は止まる。画面を離れたときは自動で一時停止し、戻ったら明示的に再開する。

通常・高難度は発射間隔1.5秒、狙いを調整して3〜5分が目安。最速の100球連射は約2.5分。練習は0.45秒間隔で短時間に流れを確認できる。画面内は最大12球。スコア・玉はゲーム内のみで、課金・換金・景品交換・外部送信はない。音は毎回初期OFF。動きを減らす設定に対応。

## 物理と判定

- 1/240秒の固定刻みで計算し、描画とは分離。同じシード・強さ・発射タイミングなら同じ動きになる。
- 釘・壁との衝突と穴の検出は線分の交差を調べ、高速の玉のすり抜けを防ぐ。
- 皿は上から見た円形の鉢を楕円に投影する。物理と描画は同じ穴の位置・半径を使う。玉の中心が穴の範囲に入ればその穴へ落ち、速度条件や別の抽選で判定を変更しない。
- 発射時の速度のばらつきだけにシード付き乱数を使う。皿では全玉に同じ中心へ向かう重力と抵抗を適用し、当たり穴へだけ吸い寄せる力は使わない。
- 皿間は見えるガイド管を約0.6秒で移動する。2Dの簡略化であり、厳密な3D流体・剛体シミュレーションではない。玉同士の衝突は省略している。
- 発射から60秒を超えた玉や計算異常の玉は、詰まり防止の回収として表示し、回収数へ一度だけ加算する。大当たりにはしない。
- 未発射玉が0になっても、動いている玉の判定が終わるまで結果に移らない。二重入賞を防ぎ、発射数＝回収数＋大当たり数＋動いている玉数を検証する。

## 短時間での確認

`/?bonus=jackpot&debug=1&seed=qa` で「検証モード」と明示された画面を開く。開始後の「検証用の操作」で、盤面／各段の縁から投入、各段の当たり・外れ穴への投入、残り玉0を確認できる。穴への投入は指定した位置に玉を置くだけで、その後は通常の物理判定を使う。指定した段以降の当たりを強制するものではない。結果もTEST RESULTとして区別する。

自然な発射から全3段を突破する再現例（強さ55、最初の1球）：練習 `seed=cafe`、通常 `seed=2`、高難度 `seed=26`。3例とも約6〜7秒で突破することを物理計算と実ブラウザで確認済み。これらのシードは当たりの指定値ではなく初期速度の再現用で、同じモードでも発射条件により結果は変わる。

## 起動・検証

Node.js 24以上で `npm ci` → `npm start`。通常と同じサーバーで静的ファイルを配信するだけで、追加サービス・依存パッケージ・APIキーは不要。検証用には `PORT=3400 DATA_PATH=/tmp/unity-bonus-check.sqlite npm start`。

- `npm test`：既存の交流ゲーム・CPUのテストと、物理・各段の成功失敗・自然な大当たり・100球の会計・フレーム刻み・上限・停止・再現性・安全回収。
- `npm run check:questions`：既存252問＋イベント90問を保持。
- `python3 test/bonus_browser_check.py --url http://127.0.0.1:3400`：375/390/414px、長押し・連打・キーボード・blurイベントによる自動停止・リサイズ・音と動きの設定、3難易度の自然な大当たり、各段の投入、玉切れ・結果・再挑戦。
- `python3 test/bonus_lifecycle_check.py --url http://127.0.0.1:3400`：カタログ通信失敗からの独立起動、フォーカス移動後の連射停止、遅い通信が新しい画面を上書きしないこと、退出時の破棄と再入場。
- 既存ブラウザ検証で、ルーム・CPU操作の回帰も確認する。

物理iPhoneのSafari、実際のスピーカーからの音、本番サイトのLive状態は別途確認が必要。PCのChromiumにスマホ幅を設定した検証と区別する。

ブラウザ自動検証の画面離脱はblurイベントを注入してハンドラを確認する。ヘッドレスChromiumでは別タブを開いてもネイティブの非表示イベントを再現できなかったため、実端末でのタブ移動・OSバックグラウンド復帰は未確認として区別する。
