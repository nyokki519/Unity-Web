# 喫茶Unity — 実装と検証

## 起動・操作

Node.js24以上で `npm ci --ignore-scripts`、`npm start`。`http://localhost:3000/?bonus=jackpot` またはホームのおまけから開始。開始画面で説明を確認し、発射・自動連射・ランダム発射を使用する。設定には威力スライダー／±、皿の拡大表示、描画品質、動きを減らす操作がある。音は初期OFF。離席・非表示では停止し、明示的に再開する。

初期24万コイン、受理された発射だけ100枚消費、大当たり100万枚。現金・課金・換金機能はない。玉切れから再挑戦可能。練習を選ぶか `&debug=1&seed=任意文字列` を付けると、各段への投入、複数玉、大当たり演出、玉切れの確認操作が現れる。練習結果は通常プレイと区別する。

## 構成とモデルの範囲

- `public/silver-ring/src/physics.js`: 許可された参考コードの物理モデル。平面の釘衝突、回転機構、解析的な皿運動、可視の段間移送。SI単位の完全剛体シミュレーションではない。参考側のゆらぎ・減衰・滞留対策を維持。
- `config.js`: 穴・皿・反発等の調整値。通常は当たり穴専用の風／遮断を無効化。開始時に明示して選べる追加難度では参考値を使う。
- `scene.js`/`fx.js`: Three.jsの盤面・皿・カメラ・演出。釘配置は物理と同じシード。旧作品の名前・台詞・ロゴを外し、深緑・木目・真鍮の独自の喫茶台へ変更。
- `main.js`/`ui.js`/`audio.js`: 入力、資源、進行、日本語表示、合成音。発射・練習投入とも同時玉数上限を適用。
- `public/js/silver-ring/shell.js`: 既存アプリと隔離した画面、戻る・停止・設定、同一オリジン検証付きメッセージ。
- Three.js0.180と追加モジュールを同梱。CDN・新規外部サービスなし。素材・許諾は [RIGHTS](RIGHTS.md) と [NOTICE](../../public/silver-ring/NOTICE.txt)。作者の許可はユーザー申告として記録している。

旧接触物理モデルは `/?bonus=jackpot&physics=1` に残す。SI-5では実際の可動コライダーを持つ回転搬送機、傾き操作、再現記録を追加。旧SI-4記録は凍結した実装で再生する。こちらの11mm・5.5g・240Hzを銀環のモデルの説明に混用しない。

## 検証

`npm test` で既存機能と物理・再現記録・HTTPヘッダーを検証する。`node tools/check-silver-flow.mjs` は自然発射を測定。`python test/silver_ring_browser.py` と `python test/silver_ring_outcomes.py` はローカルChromiumで操作と画面を確認する。

- 元コードの独立採取データと、200発射入力・240Hz・45%威力の軌跡／イベントを比較。追加難度ON/OFFとも一致。
- 自然発射3シード・計3,000入力中1,067玉受理、三段突破6回、測定条件で停滞0・未決着0。残りは送珠口／同時玉数制限で拒否し、課金しない。実機の当選確率を示す数値ではない。
- 各段30回ずつの段開始テストで成功と失敗の両方を確認。練習の大当たりボタンとは別の自然落下の検査。
- データと画面は `docs/qa/silver-ring/`。検証用投入・合成非表示イベントは実際の発射確率や実機操作の証拠と区別する。

クラウドのソフトウェア描画Chromiumによる検証であり、物理iPhone/Safari、実GPUの60fps、実機と同等の面白さは未確認。参照と同じ機能モデルでも現実の完全再現を保証しない。Renderへの通信はこの環境で制限されており、本番反映の完了確認は別途必要。

### 今回の確認結果

- Chromiumの375×844／390×844／414×844／844×390で発射、自動連射、非表示時停止、再開、手動皿カメラ、横はみ出しなし、画面退出時AudioContext解放を確認。ページ例外0件。`browser.json`参照。
- スクリーンショット：[盤面390px](../qa/silver-ring/play-390-844.png)、[皿拡大390px](../qa/silver-ring/cradle-390-844.png)、[大当たり](../qa/silver-ring/jackpot.png)、[玉切れ](../qa/silver-ring/gameover.png)。皿の写真はクラウドの遅いソフトウェア描画のため、物理を進めずカメラ補間だけを事前に収束させている。
- `outcomes.json`：練習の同時玉数30、実出力の消音と再有音化、100万枚加算、玉切れ／再挑戦、減動時フラッシュ無効。
- 既存SWからの更新・オフラインキャッシュ・進行中ページを再読込しないことを確認。ゲーム用モジュールとThree追加モジュールも事前キャッシュへ登録。
- SI-5の180玉（3難度各60玉）で停滞0・タイムアウト0・残留玉0。通常40玉の自然突破回帰テストも通過。ただしこの180玉では練習1回、通常／高難度0回の大当たり。銀環の成績とは別のモデル。
- 最終レビューは音の停止・発射ゆらぎのシード・旧版リプレイへの生操作混入を指摘。修正し、リプレイ操作の回帰テストを追加。レビュー担当の利用上限によりレビュー全体は途中終了したため、独立した全範囲レビューの完了は主張しない。
- 一時停止中は合成音のAudioContextも停止し、大当たりのカウント／完了も進めない。停止中の演出進行を再現するテストを追加して修正。

`docs/qa/cafe-motor/comparison*.json` は一次開発のSIモデル比較記録。`comparison-normal-before.json` は調整前の失敗例であり、銀環の最終比較データとして扱わない。最終の同一条件比較は `authorized-reference-baseline.json` を使う。

最終実行：`npm test` **171/171成功**（失敗0）。変更後の `silver_ring_outcomes.py` も成功。新しい有料サービス、外部AI、Renderサービス削除、APIキーの再発行、交流ゲームのデータ変更は行っていない。
