# 参照元と今回の変更

2026-10-16（日本時間）。参照: https://github.com/thirdlf03/zawa/tree/main 、確認コミット `a9118ed2efdde08ae13f44b2793c02a22445abb7`。

Gitで取得し、`src/game.ts` 全体、HTML、3Dモデルの構成・材質を確認。隔離した `/tmp` の作業コピーでViteを起動し、実際の描画画面も確認した。取得元のlockfile不整合は作業コピーだけで依存を解決した。Unity MIXの依存には追加していない。

参考になった点：Three.js/Cannonによる3D描画と衝突、立体流路、メイン視点と3段ごとのサブ視点、金属球の環境反射、画面切替。優先度による穴方向への力の付与もコードにあるが、Unity MIXはこれまでの「後から当落を操舵しない」要件を維持する。コード・モデル・HDR素材のコピーは行っていない。

Unity MIXで確認した原因：

- 自動カメラは全玉のうち最深の玉だけを見ており、回収・移送中の玉によって実際に皿内にいる別の玉を見落としていた。
- 画素密度3のスマホでも自動品質は最大1.25倍、高品質も1.5倍に制限され、CSSの表示サイズに対して描画画素が足りなかった。
- ズーム倍率が自由カメラにしか適用されず、クルーン固定視点でスライダーを動かしても近づかなかった。
- 視点移動がフレーム数に依存し、注視点は瞬時に切り替わっていた。
- 皿全体の均一な強い真鍮色、粗い反射・頂点法線により、球の輪郭と曲面の深さが読み取りにくかった。

変更：皿に入っている玉から段を選び、段間移送では2秒維持。全視点の手動ズームと時間に基づく滑らかな移動。画面密度に対応した描画（375/390/414px・DPR3では3倍）、アンチエイリアス、滑らかな曲面法線、サテン金属の皿と真鍮の縁、明るい銀球と解析的な接地影。拡大中は全景小窓を併記。皿は中央の開口へ向かう放物面へ更新し、描画と実際の衝突で共有する。SI-3として版を分離し、SI-1/SI-2は元の物理と描画を残す。

高解像度はGPU負荷も増えるため、大画面では画素予算で制限し、利用者が省電力画質へ切り替えられる。ソフトウェアGPUのFPSをiPhone実機性能の保証には使わない。
