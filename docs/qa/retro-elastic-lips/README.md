# r39 全段の縁の弾性接触・風は3段目のみ

## 方針と変更

r38では短い強い風を1・2段目へ移植せず、縁を深くする調整で代用していた。ユーザーは風を1・2段目に追加しないと明示したため、風は3段目だけに維持し、全段の縁に斜めの弾性接触を追加した。

- r38の深さ8mm・外半径37mmの落ち込みを、前回の3段目と同じ深さ3.5mm・外半径43mmへ戻した。3段目の風の加速度・周期・短い噴流のパラメータはr36/r37と同じ。
- 球が外から縁をかすめるとき、半径31mmの球中心用接触境界への到達時刻を連続判定。接触点の法線から`v' = v - 2(v・n)n`で反射方向を求める。法線速度を反転し接線速度を維持する、摩擦なし・反発係数1の皿面内の弾性接触。速さは保存し、乱数や固定の反射角で弾かない。
- 球の直線進路が開口中央を通る場合、すでに穴へ落下中の場合、離れた球、浮いている球はこの縁反射の対象外。低速の球は従来の転がり・落下を使う。全段の突破穴と外れ穴へ同じ接触処理を適用する。
- 接触後の残り時間も進めるため、フレームごとに位置を押し戻したり連続して反射させたりしない。新しい接触はカメラを揺らさない。
- 初期250発・50,000クレジット、1発200、再挑戦、入賞時の画面揺れ無効は維持。

## 検証

- `npm test`: 217件合格。接触前後の速度保存、開口中央の進路保護、落下中の球の保護、120/480Hzの接触時刻・退出軌道一致、全段の斜め接触、球同士の衝突、自然な成功・失敗、旧基準を含む。
- 3段目の正面接近の確認用軌道は、r36の保存済みブラウザ結果と24ステップのz・速度が1e-12以内で一致。単一確認軌道の一致であって、追加の縁接触を含むすべての軌道が過去と同じという意味ではない。
- 風OFFの同一条件で全段に1回ずつ明確な弾性接触を確認。r37の滑らかな曲線との進行方向差は約67/69/75度。これは代表的なかすめ方の結果で、全接触へ同じ角度を強制していない。比較個票comparison.json、図trajectories.png。
- Chromium実ブラウザでも3段の接触・実描画位置・球同士の衝突を確認。1・2段目の送風作動0回、3段目1回、ファンは3段目だけと検査。contacts-browser.jsonとlip-stage-*.png。
- 250発×500回、送風ON・発射力45%・入口割込みOFF。大当たりあり182/500=36.4%、総発射125,000、合計233当たり、返球0、残留球0、不完走0。1段目5,732/16,976=33.8%、2段目1,444/5,732=25.2%、3段目233/1,444=16.1%。summary.json、seeds-*.json。
- 自然試行で縁の弾性接触は1段目23,372回、2段目10,234回、3段目2,072回発生。全試行の正味250発、各段の到達数=突破+外れ、最終段入賞数=大当たり数を検査。

## 制約と再現

既存の皿面拘束モデルでの接触近似。実物のトーラス形状の縁と球の完全な3D剛体接触ではない。球中心の有効接触境界と開口を別に扱い、穴へ落ちる軌道を一律に跳ね返さないための近似を含む。接触後は通常の重力・皿の減衰が働くため、プレイ全体が等速になるわけではない。

設定は`public/silver-ring/src/config.js`の`bowls.contacts.grazeEnabled/grazeRadius`、処理は`bowl-forces.js`の`advanceLipGraze`。`node scripts/silver-lip-comparison.mjs`と既存の全経路測定スクリプトで再現できる。

実機iPhone Safari、実測fps、本番Renderの反映完了は未確認。版表示r39。
