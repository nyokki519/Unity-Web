## 測定できた操作上の問題

390pxでvisualViewport.scale=390/640。DOM矩形にこの倍率を掛けた見かけの寸法：額面ボタン約27.4×28.6px、Max/Min約35.3×21.9px、上部アイコン約36.6×36.6px、DEAL約90.2×41.4px。主要操作は少なくとも44×44 CSS pxを設計目標とし、単なる画像拡大でなく独立したヒット領域・余白を確保する。これはWCAG全項目の監査・適合認証ではない。

14pxのCanvas残高文字は390pxで約8.5px相当。Canvasに焼き込まれた数字・ラベルは通常のテキスト拡大に追従しにくい。metaのuser-scalable=noもズーム利用を制限する。DOMボタンにはaria-labelとフォーカス表示があり、この強みは維持する。スクリーンリーダーでカードや精算を十分理解できるかは今回未検証。

## 推奨する独自デザイン

「Unityのプライベートテーブル」として、深いネイビー(#101B24)、エメラルド(#164C43)、アイボリー(#F1E8D7)、控えめな真鍮(#B59B67)へ統一。全面の緑画像、金色の筆記体、黄色の点線円、画像ボタン、青白いOS風ダイアログは個別に置き換える。単なる配色変更ではなく、構図・ボタン形状・文字組・素材・動きを作り直す。名称はUnity BACCARATを中心とし、コミュニティのハート/カップ意匠をトランプ、チップ、中央の小さな刻印へ展開。Unity Technologiesのロゴは使用しない。

## 実装の考え方と順序

提案は「レスポンシブな2D/DOMテーブル＋絞るカードのみ3D変形」を推奨。全面3Dは照明/反射を統一しやすいが、スマホの負荷・文字の読みやすさ・入力制御の検証範囲が増える。現行の固定Canvasの着せ替えは安いが、小さなUIとPC余白を解消しにくい。

1. カード主役のスマホ1画面、ベット操作、結果の表示を作る。
2. 一枚の手動絞りを通常速度で仕上げ、音と直接操作を確認する。
3. 専用のチップ・フェルト・ボタン・タイトル・パネルへ同じ意匠を展開する。
4. 罫線・音設定・PC配置、375/390/414px、動き軽減、キーボードを検証する。
5. 現行ルール・シュー・保存・精算テストに加え、絞り途中の中断・連打・再読込と実描画FPSを検証する。

既存の8デッキ、コミッション、乱数、残高、保存トランザクションは維持。現行UI資産は参考として扱い、原典と画素一致させる品質目標は今回から適用しない。今回の成果物は現状レビューと具体策であり、改修済み画面や性能達成の証拠ではない。
