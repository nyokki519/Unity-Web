# 直接操作の大判カード卓 / 2026-10-28

ユーザー要望：バーではなく自分の指でめくる。小さなカードと設定ダイアログの印象をなくし、バカラの卓で最後のカードを覗く感覚へ近づける。設計・計画の追加承認不要という既存指定に従い実装する。

- スライダー主体のダイアログを、大判カード主体の全画面テーブルへ変更。余白を削りカード実幅をスマホ画面の約8割以上へ拡大。すでに公開したP/Bのカードと点数を周辺に表示し、最後の一枚を待つ文脈を保つ。
- カードを直接触り、上へ引く量で開く。下へ戻せば覗き戻せ、離せば保持。左右のつまむ位置が曲面の傾きへ反映。速く長く払った時だけ短い全開へ。誤タップ・水平移動・二本指・pointercancelで勝手に確定させない。
- 純粋なHandSqueezeモデルで移動と完了意図を検証。pointerIdを保持し、一連の操作を別の指で乗っ取らない。スマホでは約260px以内のストロークを基準にする。
- 指位置の手掛かりと「端をつまんで上へ」の誘導をカード上に置く。補助rangeは閉じた「補助操作」内。カード自体にキーボード操作、全開/自動/短縮は維持。
- 既存の両面WebGL曲面を細密化し、角のつまみ方・軽い俯瞰・最後の公開への緩い寄りを追加。別カード/偽のピップを見せず、完全公開まで点数は更新しない。
- gripXを絞りの化粧チェックポイントへ後方互換で保存。中断/再読込/古い保存はカード・精算を変えず復帰。GPU喪失では直接操作可能な簡易表示。

検証：直接タッチとマウス（バーを開かない）、左右の角、途中戻し/保持、誤タップ、二本指、短い/長い払う操作、390pxでの実カード幅、375/390/414pxと日英130%、点数/二重精算/復帰、描画負荷、既存回帰。実機iPhoneと手触りの最終判断は自動テストと区別する。


## 検証結果

- 全体392 Nodeテスト、失敗0。4件の手操作テストで上/下移動、左右の角、長い速い払う意図、タップの誤確定防止、極端な画面サイズを検証。カード抽選・整数精算・保存・演出独立乱数も従来どおり。
- 実ブラウザの直接タッチ（CDPの実入力）・マウス・カード自体の矢印/Home/Endを確認。補助バーを開かず、覗き戻し・保持・二本指が操作を奪わないこと・速い払う操作・自動から手動への受け取り/再開を確認。
- 390pxの実カード描画幅は約338px（画面幅の87%）。375/390/414px、日英130%、通常の6枚配札・横置きの第三カード、説明/操作との重なりなしを確認。通常卓のスマホカードは64→76pxへ拡大し、第三カードは横置きへ変更。演出時も元の置き方を維持。
- すでに見えているカードと点数だけを全画面卓に引き継ぐ。完全に開くまで新しい合計点は出さない。古い化粧セーブのgripX欠落も受理し、カード/金額/計画は変更しない。
- GPU喪失時の簡易表示、BGMの停止/再開、配札途中のリロード、設定の次ラウンド適用、旧バカラ操作・既存ゲーム回帰を確認。
- 華やか/自動絞り各3ラウンドのChromium rAF間隔：390px中央値16.7ms/95%点16.8ms/最大50ms、1920px中央値16.7ms/95%点16.7ms/最大66.7ms。Long Taskともに0。実機FPSではない。
- 代表画像・操作検証動画（無音）は `qa/hand-table/`。動画は操作の確認用で、勝率を示さない。
