# 無料枠での公開準備

公開方針：Renderの無料Web Service、Docker、一つのインスタンス。GitHubはコードの保管先。GitHub Pages単体ではリアルタイム対戦サーバーを動かせない。

## 準備済みの内容

- `main` ブランチにアプリと `render.yaml` を配置する。
- 設定は `plan: free`。有料ディスク・有料インスタンスを要求しない。
- 無料版の保存領域は一時的。サーバーの再起動・再配置でルームが失われる。その制約をアプリ内にも表示する。
- `RENDER_EXTERNAL_URL` を使って、実際に割り当てられたHTTPS URLへQR参加を誘導する。架空の本番URLを指定しない。
- Dockerのヘルスチェックは実際の `PORT` に追従する。公開チェックのパスは `/api/health`。
- カップとハートのブランド図柄を継承。アプリ用のAPIキーは不要。

無料枠の利用可否・休止条件・利用上限はRenderの申し込み画面で確認する。無料枠が利用できない場合に、有料プランへ自動で切り替えない。

## 既存サービスを更新する場合

既存のRenderサービスの対象ブランチを `main` に合わせ、Auto-Deployが有効ならmainの更新を待つ。無効ならManual Deployから最新コミットを指定する。サービスの削除・作り直しやAPIキーの再発行は不要。

## 管理APIを新たに接続する場合（任意）

1. https://dashboard.render.com/ でRenderに登録またはログインする。
2. Account Settings → API KeysでAPIキーを作成する。
3. このクラウド環境の個人シークレット `RENDER_API_KEY` に安全に登録する。チャット・リポジトリ・アプリの環境変数へキーを貼らない。
4. クラウド環境の設定変更を保存し、必要な環境Publishを完了する。環境のPublish自体はサイト公開ではない。
5. 接続後、アシスタントが所有ワークスペースを確認し、無料サービスを作成する。実URLとデプロイ完了を確認し、HTTPS・WSS・ルーム参加・QR・共有を検証する。

API通信の許可先は `api.render.com`。実サイトの検証には、サービス作成後に判明した実際のホスト名への接続も必要になる。秘密の値は出力しない。

## Renderの画面から公開する場合

RenderのNew → BlueprintでGitHubリポジトリ `nyokki519/Unity-Web` を連携し、ブランチ `main` の `render.yaml` を使用する。作成内容が無料Web Serviceで、有料ディスクがないことを確認する。画面が異なる場合はNew → Web Serviceから同じリポジトリ・ブランチ、Docker、Free、ヘルスチェック `/api/health` を指定する。

サービスが割り当てた実際のURLが本番URLになる。GitHubリポジトリのURLはゲームを遊ぶURLではない。

## 公開後のチェック

- HTTPSのトップ画面と `/api/health` が200。
- 二つの端末からルーム作成・参加・準備・回答・同時公開・会話・次へ。
- 公開前に他人の答えが見えない。
- QRが実際のHTTPS URLを向く。
- 再接続とホスト引き継ぎ。
- PNG保存、iPhone Safari / Android実機の共有とPWA。
- 無料サービスの再起動時は新しいルームを作る運用を案内。

管理APIの接続と本番のデプロイ完了を確認するまでは、公開済みとは扱わない。
