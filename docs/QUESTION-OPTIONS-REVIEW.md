## 代表的な修正前／修正後

| モード・設問 | 修正前 → 修正後 | 理由 |
| --- | --- | --- |
| ALIGN「作業するなら？」 | 静かな場所／少し音のあるカフェ → 静かな場所／少し音のある場所 | 場所の種類と音の大小を混ぜず、音環境の好みで比較する。 |
| PREDICT「作業するなら？」 | 同上。対応するALIGNと質問・選択肢・タグを揃えた。 | 本人の答えと他の人の予想が同じ意味を持つようにする。 |
| LINE「友達との集まり、理想の人数は？」 | 少人数〜たくさん（0〜100）→ **2〜15人、1人刻み** | 人数を直接答える。人数の多さだけで冒険心を採点しない。 |
| RANK「休日に大切にしたいのは？」 | 余白・時間／人とのつながり／新しい体験／健康／創造 → のんびりする／親しい人と会う／初めての場所へ出かける／体を動かす／料理や工作 | 同じ休日の行動として順位をつけ、その理由を話せるようにする。 |
| AUCTION「理想の一週間に100ポイント」 | 健康・お金など汎用的な価値名 → 「来週、自由に使える時間」の睡眠・運動／人と話す／家計を見直す／学ぶ等8活動 | 配分する対象と選択肢を一致させる。各問で8項目・合計100ポイントを維持。 |
| QUICK「今、行ってみたいカフェは？」 | 店名を求めるようにも読める → 「特定のお店がなければ、どんなカフェがいい？」を補足 | 店名を知らなくても参加できる。自由回答を維持。 |
| 価値観ランキング「休日に大切にしたいもの」 | 休息／友達／新しい体験／趣味 → 体を休める／友達と過ごす／初めてのことをする／趣味に打ち込む | 行動として比較できる粒度に揃える。 |
| みんなの境界線「待ち合わせに何分早く着きたい？」 | 0分〜100分 → **0〜30分、1分刻み**。両端は「ちょうどの時刻／30分前」 | 分数で回答・保存・表示・集計する。例えば15分と30分の平均は22.5分。 |
| この回答、誰でしょう？「最近ちょっと笑ったこと」 | 汎用の「選んだ理由」→「何があって笑ったのか、一言で」 | 選択式ではない短文回答に合った会話補助。匿名自由回答を維持。 |
| 共通点クエスト「みんなが好きな飲み物」 | 汎用の「選んだ理由」→ 飲み物を出し合い、見つからなければ似た好みを話す | 一致の強制を避けつつ、チームで探す行動を具体化。自由記述を維持。 |
| 架空のカフェ会議「読書好きが集まるカフェ」 | 全企画共通の公園・駅前／一般メニュー／一般内装 → 図書館そば・読書会に集まりやすい駅近／片手で食べられる菓子／手元灯・読書会テーブル等 | 15の企画それぞれ専用の立地・メニュー・内装を用意。好みを正解扱いしない。 |
| エピソードの持ち主「思いがけない親切」 | 汎用の「選んだ理由」→「どんな親切で、そのときどう感じたか、話せる範囲で」 | 体験を話す形式に合わせる。見出し＋長文、本人の会話時間を維持。 |

選択肢IDは維持。中立的な好みから根拠のない性格・価値観を推測していたタグを取り除き、ランキングと配分のタグも回答内容に合わせた。カフェの費用は予算100万円、組合せ60〜130万円を維持し、全15問×27通りで予算内・超過の両方があることを検査した。

数値尺度は任意の `scale: {min,max,step,unit}` を質問に持たせ、サーバーで範囲・刻みを検証する。ブラウザの入力、送信済み表示、匿名分布、平均・最小・最大、自分の位置が同じ単位を使う。集計の価値タグ計算とグラフ座標だけを0〜100に換算する。司会のお題編集でも単位・範囲を変更でき、数値尺度のない既存ラウンドは従来どおり0〜100として扱う。モード名も「数字で見る違い」「100ポイントの配分」に整えた。

## モード選択画面

修正前は375pxでカードが2列となり、標準ラジオボタンの余白と複数行にまたがるグリッド配置のため、ボタンと本文の間隔が実測3pxしかなかった。今回のChromiumでは矩形の交差までは再現しなかったが、文字が小さく窮屈な配置は確認できた。

ラジオボタンと本文グループを別の列に置き、14pxの間隔、本文の折り返し、モバイル1列を設定。カード全体を暗黙のlabelとして押せる構造と、標準ラジオボタンの矢印キー操作を保ち、選択時の背景・枠、フォーカス枠を明示した。深緑・アイボリーは維持。

## 検証・起動

- `npm test`：51件。実HTTP/WebSocketの6人・15人、匿名保護、再接続、権限、締切、二重操作等の既存テストと数値尺度・選択肢の回帰テスト。
- `npm run check:questions`：既存252問＋イベント90問の形式・ID・タグ・選択肢構造を検証。
- `python3 test/question_ui_check.py --url http://127.0.0.1:3201`：375/390/414pxの全カード、長文、画面外はみ出し、44px以上のタップ領域、本文タップ、矢印キー。
- `python3 test/numeric_ui_check.py --url http://127.0.0.1:3201`：独立した2ブラウザで2人・15人、15分・30分を送信し、平均8.5人・22.5分、匿名分布の位置、送信済み単位表示を確認。
- `python3 test/browser_check.py --url http://127.0.0.1:3201`：既存6モードの同期・リロード・共有画像・司会交代。375〜1440pxで横はみ出しなし。
- `python3 test/events_browser_check.py --url http://127.0.0.1:3201 --games BOUNDARY CAFE`：6人・15人の独立ブラウザ、各2ラウンド、予算超過、未回答、スキップ、代表の復旧・司会交代。
- 残りのイベント4ゲームも同スクリプトの `--games VALUES WHO QUEST STORY` で6人・15人を検証。

起動は Node.js 24以上で `npm ci` → `npm start`（標準 http://localhost:3000 ）。検証用は `PORT=3201 DATA_PATH=/tmp/unity-question-check.sqlite npm start`。新しい外部サービス・APIキーは不要。許可されたmainへの反映に合わせて `render.yaml` の対象ブランチもmainに揃えた。
