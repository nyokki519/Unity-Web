# 1人で動作確認する（CPUテスト参加者）

1. 通常どおりルームをつくる。既存MIXでもイベントゲームでも利用できる。
2. 待合室の「ひとりで動作確認」で「CPUを1人追加」を押す。複数人の画面を見たい場合は「合計6人にする」「合計15人にする」を使う。人数にはあなたと実際の参加者を含む。
3. 自分の「準備できた」を押し、START MIX。CPUは準備済みになっている。
4. 自分は回答またはパス。CPUは約1〜3秒で回答する。イベントでは司会が締切・公開・正解公開・次ラウンド・終了を操作する。既存MIXでは選んだ公開タイミングの設定に従う。
5. CPUの削除や人数変更は待合室で行う。終了後は「待合室へ戻る」または「もう一度、MIXする」から戻れる。

追加・削除できるのは司会だけ。合計人数ボタンはCPUだけを増減し、実際の参加者を退出させない。人だけで指定人数を超える場合、その人数ボタンは使えない。上限は従来どおり24人。司会以外にはCPU操作ボタンを表示しない。

## CPUの振る舞い

- 既存ALIGN/PREDICT/LINE/RANK/AUCTION/QUICKと、VALUES/WHO/BOUNDARY/QUEST/CAFE/STORYに対応。
- 二択・順位・配分・数値は、設問の回答形式と範囲に沿う自動回答。予想では自分の回答に投票しない。
- 自由回答、共通点、体験談、カフェ案は**動作確認用の架空のサンプル**。質問の内容を理解して会話する生成AIではない。外部AI・課金サービス・APIキーは不要。
- 人がいるチームは人が代表になり、相談・提出を操作する。CPUだけのチームは自動提出。カフェの自動案は予算内の選択肢を選ぶ。
- 参加者一覧のCPU表示と、ゲーム中の「CPUテスト中」表示で区別。集計にはCPUも参加者として含まれるため、実際の参加者の価値観の分析には使わない。
- ブラウザを閉じてもCPUは司会にならない。接続中の人がいない間はCPUの回答処理を止める。人が再接続すると再開する。
- リロード・SQLiteからの復帰に対応。Render無料枠でサーバーが再起動して一時保存データ自体が消えた場合は、従来どおり新しいルームをつくる。
- 一時停止中や締切後には回答しない。提出済みの回答や投票を上書きしない。CPUの認証情報はクライアントへ送らず、CPUとしてブラウザから認証することもできない。

## 検証

- `npm test`：CPUの権限、上限、人数増減、全12モード、2/6/15人構成、締切・一時停止・匿名保護・自己投票禁止・司会引き継ぎ防止・保存復帰、および既存テスト。
- `npm run check:questions`：既存252問＋イベント90問。
- `python3 test/cpu_ui_check.py --url http://127.0.0.1:3302 --output /tmp/unity-cpu-qa`：1つの実ブラウザでCPUを追加し、既存6モードとイベント6ゲーム（イベントは各2ラウンド）を操作。375/390/414pxで人数変更・リロード・タップ領域・横はみ出しを確認。
- `python3 test/events_ui_controls.py --url http://127.0.0.1:3302`：人だけでの編集・追加・実時間の締切・絵文字・リロード・非表示・動きを減らす設定を回帰確認。
- LINEの既存テストが固定の0〜100だけを想定していたため、人数尺度の質問でも合法な値を送信して平均・分布を検査するよう修正。
- 自動投票が届いても画面の予想人数が初期値のままだったため、入力中の選択を消さずに人数だけを更新するよう修正。

CPU検証は複数端末の通信や会場Wi-Fiの検証を代替しない。物理iPhoneのSafari操作と本番のLive確認は別途必要。

起動はNode.js 24以上で `npm ci` → `npm start`。検証用に別DBを使う場合は `PORT=3302 DATA_PATH=/tmp/unity-cpu-qa.sqlite npm start`。

2026-10-15の結果：自動テスト76/76、全342問の形式検査、CPU操作の実ブラウザ検証、人のみの実時間締切を含む回帰確認が通過。
