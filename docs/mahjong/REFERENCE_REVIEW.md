# 麻雀参考実装レビュー

調査対象は `gimite/mjai` と `kobalab/Majiang`。目的は、ルールエンジン・AI・表示を分離する設計、合法アクションを明示する対局モデル、読みやすい河と牌操作を比較すること。既存Unity MIXのサーバー権威モデルを維持し、互換性・運用・ライセンスのリスクが高いエンジン置換は採用しなかった。

| 観点 | 参考にした設計上の利点 | Unity MIXへの適用 |
|---|---|---|
| ルールと操作 | 対局状態とプレイヤーの操作を明示的に分ける | 既存のサーバー側合法アクションと局状態を維持し、CPUはその合法手からのみ選ぶ |
| AI | 向聴・受け入れ・安全度を別の評価軸として扱う | 向聴数、見えている受け入れ、公開ドラ、現物・筋を段階的に評価。直ちに聴牌する鳴きは役のある待ちを確認 |
| 表示 | 牌の形・サイズ・卓上位置を独立して扱う | 独自SVGの手牌・河・副露・ドラ表示、ツモ牌の区別、狭い画面の手牌横スクロールを実装 |
| 情報の境界 | クライアントに公開状態と非公開状態を分ける | 他家の手牌・山・未公開カンドラをAIや他プレイヤーのビューへ渡さない |
| 入力 | 操作候補を現在の状態に限定する | 既存アクションUIと権威サーバーを維持し、牌選択のキーボード移動も追加 |

## 権利・依存関係

- `kobalab/Majiang` のリポジトリはMIT表記。ただしREADMEが案内するcore・AI・UI等の別パッケージは個別に依存・ライセンスを確認する必要がある。今回は取り込んでいない。
- `gimite/mjai` のREADMEとgemspecにはNew BSD系の記載がある一方、調査時点でチェックアウトに独立したLICENSE/COPYING本文を確認できなかった。今回はコード・素材を複製していない。
- ユーザーから利用許可の申告を受けているが、許可範囲や各依存パッケージのライセンスが曖昧な状態で上流コード・画像・音をバンドルする必要はなかったため、どちらも実行時依存にしていない。
- 新規ランタイム依存、上流コード、牌画像、音源は追加していない。SVG牌絵とWeb Audio効果音はUnity MIX内で新規作成。

## 検証で見つけて直した差

- 対戦状態の `kanDoraIndicators` は未公開の将来表示牌を含み得るため、CPUの公開情報カウントから除外し、現在公開中の `doraIndicators` のみに限定。
- 鳴かれた牌は河に残り、副露にも表示される。受け入れ計算では `called` の河牌を除いて二重カウントを防止。
- リーチ前の河にある牌もリーチ後の現物として安全。その判定を修正し、回帰テストを追加。
- 鳴いて即聴牌する選択は、採点器で役のある待ちを確認してから候補にする。
- 不正な牌データのラベルを属性やボタン文字へ出す経路をエスケープし、XSS回帰テストを追加。

## 残る制約

CPUは軽量な打牌ヒューリスティックで、相手モデル・押し引きの期待値計算・深い局面探索を持たない。上流AIの強さに匹敵すると主張しない。実機iPhone Safari、端末ごとの音の聞こえ方、対局の長時間負荷は未確認。自動テストとChromiumでの4席同期は確認済み。
